# 학교축제 방문자 사전등록 및 출석확인 앱

## 구성
- `visitor_app/app.py`: 방문자 사전 등록 및 QR 발급
- `attendance_app/app.py`: QR 촬영·출석 처리·통계
- `google_apps_script/Code.gs`: 일반 구글 계정의 스프레드시트와 연결하는 API
- `requirements.txt`: Python 패키지

## 중요한 데이터 파일명 안내
Google 스프레드시트는 실제 CSV 파일과 다른 문서 형식입니다. 스프레드시트 문서 제목을 `학교축제외부방문자.csv`로 지정할 수는 있지만, 그 자체가 CSV 파일이 되는 것은 아닙니다. 이 프로젝트는 구글 스프레드시트 문서를 원본 데이터로 사용합니다. 필요하면 스프레드시트에서 파일 > 다운로드 > 쉼표로 구분된 값(.csv)으로 내려받을 수 있습니다.

## 1. 구글 스프레드시트 준비
1. 일반 구글 계정으로 Google Sheets에서 빈 스프레드시트를 만듭니다.
2. 문서 제목을 `학교축제외부방문자.csv`로 지정합니다.
3. 주소에서 `/d/`와 `/edit` 사이의 문자열을 복사합니다. 이것이 Spreadsheet ID입니다.
4. `방문자`라는 시트 탭을 만듭니다(스크립트가 없으면 자동 생성합니다).

## 2. Apps Script 연결
1. 스프레드시트에서 확장 프로그램 > Apps Script를 엽니다.
2. 편집기의 기본 코드를 지우고 `google_apps_script/Code.gs` 내용을 붙여넣습니다.
3. `SPREADSHEET_ID`에 복사한 ID를 넣습니다.
4. `APP_SHARED_KEY`를 충분히 긴 임의 문자열로 바꿉니다. 예: 비밀번호 관리자에서 생성한 32자 이상 문자열.
5. 저장합니다.
6. 배포 > 새 배포 > 유형 선택(톱니바퀴) > 웹 앱을 선택합니다.
7. 실행 사용자: 나, 액세스 권한: 모든 사용자로 설정하고 배포합니다.
8. 권한 승인 화면에서 본인 계정으로 승인합니다.
9. 표시되는 웹 앱 URL(`/exec`)을 복사합니다.

## 3. GitHub 저장소 만들기
1. GitHub에서 새 저장소를 만듭니다.
2. 이 ZIP의 파일을 저장소 루트에 업로드합니다.
3. `visitor_app`과 `attendance_app` 폴더 및 `google_apps_script` 폴더가 루트에 있는지 확인합니다.
4. 저장소는 Private로 운영하는 것을 권장합니다. Streamlit 앱 주소는 별도 관리자 공유 대상으로 관리합니다.

## 4. Streamlit secrets 설정
각 Streamlit 앱을 별도로 배포합니다.
- 방문자 앱의 Main file path: `visitor_app/app.py`
- 출석 앱의 Main file path: `attendance_app/app.py`

각 앱의 Streamlit Cloud 관리 화면에서 Settings > Secrets에 다음을 입력합니다.

```toml
APPS_SCRIPT_URL = "여기에_배포된_Apps_Script_exec_URL"
APP_SHARED_KEY = "Code.gs에_설정한_동일한_비밀문자열"
```

두 앱 모두 같은 값을 사용합니다. `secrets.toml`을 GitHub에 올리지 마세요.

## 5. 테스트 순서
1. 방문자 앱에서 테스트 방문자를 등록합니다.
2. 화면의 QR코드를 저장합니다.
3. 구글시트 `방문자` 탭에 한 행이 추가되었는지 확인합니다.
4. 출석 앱에서 QR 이미지를 업로드하거나 카메라로 촬영합니다.
5. `입장 확인 및 등록완료 처리`를 누릅니다.
6. 시트의 `등록완료`가 `완료`로 바뀌고 `입장일시`가 기록되는지 확인합니다.
7. 같은 QR을 다시 처리해 중복 입장이 차단되는지 확인합니다.
8. 관리자 통계에서 등록·입장·미입장 수를 확인합니다.

## 운영상 유의사항
- Apps Script 웹 앱 URL과 공유 키는 외부에 공개하지 않습니다. Streamlit Secrets에만 보관합니다.
- 관리자 3~4명은 동일한 출석 앱 URL을 사용하면 됩니다.
- 출석 처리 시 Apps Script `LockService`로 동시에 들어오는 입장 요청을 직렬화해 중복 처리 위험을 줄입니다.
- QR에는 이름·전화번호가 아닌 무작위 토큰만 들어갑니다.
- 실제 운영 전 테스트 계정으로 여러 기기 동시 접속, 네트워크 장애, 카메라 권한, 중복 QR, 잘못된 QR을 확인하세요.
- 개인정보 수집·이용 동의 문구, 보유기간, 파기 시점, 접근 권한은 학교의 개인정보 처리 기준에 맞게 확정해야 합니다.
- 공개 웹앱은 인터넷 연결이 필요합니다. 축제 장소의 Wi-Fi와 모바일 데이터 품질을 사전에 점검하세요.
